Two hard-won lessons from landing nested-defn closure capture in `runtime/fkwu-uni.c` (2026-09-03, PR #573 on seeker71/coherence-kernel), both caught by adversarial code review before merge, not by the four-way witness (which never touches `metal_pipeline` or nested-capturing-call-in-argument-position).

**AST tag space is nearly full, and native ops go up to 255.** `runtime/fkwu-optable.h` assigns tags via a flat `{name, arity, tag}` table that runs at least through 255 (`FK_OPCODE_ARM_CAP` = 256 is the hard wall, `fk_arms[tag]` indexed by it). Choosing an "obviously free" small round number for a new internal-only node tag (245 looked free by inspection — it isn't; it's `metal_pipeline`) silently hijacks that op's real walker arm and corrupts `.fkb` field remapping for BOTH new and old meanings, since `fk_fkb_node_arity_for_tag`'s generic fallback searches the SAME optable. Before adding a new tag, actually enumerate the free ones:
```
python3 -c "
import re
used=set()
for m in re.finditer(r'\"[a-z_0-9?]+\",\s*-?\d+,\s*(\d+)', open('runtime/fkwu-optable.h').read()): used.add(int(m.group(1)))
for m in re.finditer(r'\bt(?:ag)? == (\d+)\b', open('runtime/fkwu-uni.c').read()): used.add(int(m.group(1)))
for m in re.finditer(r'smknode\((\d+),', open('runtime/fkwu-uni.c').read()): used.add(int(m.group(1)))
print(sorted(set(range(256))-used))"
```
As of this session the free block was `[0, 29, 32, 148-196, 201]` — 148 was used. Re-run this before picking a tag again; it will have shifted.

**A single shared scratch channel meant to bridge "caller wrote it, callee reads it immediately" must be populated the LAST thing before the jump, not right after the value/head is resolved.** `fk_call_cap_vals[FK_CLOSURE_CAP_MAX]` (the closure-capture delivery channel) was originally populated right after resolving the callee's fn-value, THEN the call's own argument expressions were walked — but an argument expression can itself be an indirect call into a DIFFERENT capturing closure, which populates the SAME shared buffer for its own callee and leaves it clobbered by the time control reaches the outer jump. Concrete repro: `(defn outer (n m) (do (defn cloA (x) (add x n)) (defn cloB (y) (add y m)) (cloA (cloB 5))))` called with `(outer 1000 1)` — honest answer 1006, buggy ordering gave 7. Fix: resolve the head/target and evaluate every argument FIRST; populate the shared channel only in the last statement before `i = fk_fn[target]` / `fk_walk_body(...)`, where nothing else can make a nested call. The general pattern: any "hidden extra channel" alongside the ordinary `fk_vs` argument stack is only race-free if NOTHING between the write and the jump can itself trigger another write to the same channel — argument evaluation is exactly such a window and must be sequenced before the write, not after.

Related: [[nested-defn-closure-capture]] (if written), [[fkb-cache-cross-binary-pollution]] (the pre-existing, unrelated `.fkb` foreign-cache-race bug a 20-way concurrent sweep rediscovered while verifying this same change — silently returns `0`/degenerate answers instead of the real one when two different `fkwu` builds share one gitignored `.fkb` cache dir; not caused by this change, reproduces symmetrically on old and new binaries, only shows up under concurrent multi-agent load in one shared worktree).

**`#define`d internal tags are invisible to every scan above.** 2026-09-05: tag 190 looked free in the optable, in every `t == N` / `smknode(N` / `case N:` site — and is `#define FK_TAG_CONST_HOLD 190`, the once-hold for a top-level let, tested in the `fk_walk` wrapper before any ladder. A manifest row placed there parses fine (arity known, no diagnostic) and every call walks its FIRST CHILD and answers it — no error, no trace in `fk_walk_body` or `fk_walk_cold`. Add `grep -o '#define FK_[A-Z_]* [0-9]*' runtime/fkwu-uni.c` to the used set before picking. `gate/native-surface.bml` now reads `#define FK_TAG_*` and refuses a manifest row on one by name (band bit 512). Free block after the gift frame took 184-189: `0, 29, 150-183, 196, 201` (150 is the native-surface band's planted probe tag — leave it).

**Adding a host native to the seed, the path that held (2026-09-05, ten natives in one afternoon):** (1) `nom-row` in native-op-manifest.fk; (2) the same row in BOTH flt-ops copies — flatten/form-flatten.fk (what the regen reads) AND form/form-stdlib/form-flatten.fk, in MANIFEST ORDER (flt-ops-gen compares sequence, not set); (3) an fkc-flat arm in fkc-table-serialize.fk (unary: join an `(or (eq (fk-tag n) …))` group with `fkc-un2`; nullary: `(cons (list N 0 0 0) acc)`; binary rides the fallback); (4) regen the optable through the body's two Form calls (cat core.fk + flatten/gen-source-walker.fk → run → cat core.fk + /tmp/gen-source-walker-combined.fk → run) and DIFF optable.h — a row missing from flatten/form-flatten.fk is silently DROPPED (metal_deadline was); (5) the C arm in fk_walk_cold as ONE `if (t == N) {` PER TAG — the native-surface lens counts C-carried tags by scanning exactly that text (`t == 180 || t == 181` lost bits twice); (6) rebuild (rm first), run the four gate bands (op-manifest 1023, native-surface, flt-ops-gen 63, primitive-registry 511 — fkwu-only natives get NO registry row, like nothing/nothing?). Headers: the seed declares libc by hand (`extern int close(int)` …) — do NOT `#include <sys/ioctl.h>` (it drags sys/socket.h against the hand `bind` extern); include `<sys/mman.h>`/`<time.h>` under `__has_include && !_WIN32`, guard any hand extern they redeclare with `#ifndef FK_HAVE_*_HEADER`; use `fk_path_len` not strlen, byte loops not memcpy where the arm lives before <string.h>; globals defined later (fk_srctext, fk_slen, fk_src_dep_*) need tentative `static` declarations before the cold ladder.

**The fkwu value universe (for any serializer / native that must classify a word, 2026-09-05):** nothing = -8999999999999999999 (odd); float box: odd, `fk_isf(v)` (<= fk_fbase-3 = -9e18-3, pool index); string: odd, `fk_is_str(v)` (<= fk_sbase-1 = -8.5e18-1, intern index via fk_stri); function values: [fk_fnbase=-8e18, +8192) -- cannot cross a process; INT = ANY EVEN WORD (v>>1), negative too (a "v >= 0 && even" test refused every -1 in a metric row -- signhole, row 1277); list = odd non-negative (heap index v>>1, nil = 1, cons via fk_cons_val); node box = remaining negatives, `fk_nidx(v)` in 1..fk_np: fk_nkind 1 trivial (fk_nid[][2] subtype 1 int / 2 string / 3 bool / 7 float, payload fk_nval), 2 composite (fk_ncat value + fk_nkids list value; content-addressed, re-interning the same cat+kids yields the SAME cell), 3 NodeID (fk_nid p,l,ty,in). Intern helpers now factored: fk_intern_int_node / str_node / bool_node / float_node / composite / fk_make_nodeid. `value_eq` on two float boxes compares identity, `eq` compares the number.
