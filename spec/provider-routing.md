# Choosing where an inference runs

A `provider.job` names the owner, source content ID and occurrence, and can offer a local and an external resident request. Each request binds its own model, vocabulary, history, occurrence and input. A matching local port takes precedence. If that port starts and loses its result, the broker records the fault as unserved. A port mismatch can select the external request when both people have authorized that exact disclosure.

| Entry | Inputs | Result |
|---|---|---|
| `provider/offer.ck` | Channel on fd 3, job on stdin | Exact scope an owner can review and grant |
| `provider/dispatch.ck` | Channel on fd 3, local port or `no` on fd 4, job on fd 7. The resident uses fd 5 and stdin for requests and replies. | `provider.turn` containing the recorded decision and any local answer |
| `provider/answer.ck` | Fitted seed language model on fd 3, recipient’s public roster on fd 4, published letter on stdin | Answer bound to the ticket and resident request |
| `provider/signing-bytes.ck` | Answer on stdin | The 32 raw bytes a provider signs with its listener key |
| `provider/seal.ck` | Answer on stdin, 64-byte Ed25519 signature on fd 4 | Sealed answer for the owner |
| `provider/resume.ck` | Channel, job, saved decision and resident assignments on fds 3, 4, 7 and 8. Local answer or sealed external answer on stdin. | `provider.settlement` containing a reason and the resulting assignments |

The broker stores decision records by content ID in the owner's private directory. Each records the job, route, dispatch, selected request and outcome or reason. The foreign mailbox receives a frozen packet containing only the protected roster ID and the approved external request. The owner's signed grant sets its source, recipient, purpose and expiry. The recipient independently signs an invitation for the same ticket. The circle broker checks both under its lock and samples time again before publishing. A replay uses the existing letter. Withdrawal after publication can prevent use of a late answer. Bytes delivered before withdrawal remain at the recipient.

An external answer signs its complete dispatch ID and resident result, including the returned value. The owner verifies the protected roster and listener key, checks current permission after verification, then matches the answer against the original assignment. The owner retains the prior assignments on refusal. Re-enrollment under another episode changes the signed scope and dispatch even for otherwise identical requests. A valid signature establishes which enrolled key vouched for those bytes. A participant still needs independent evidence to establish model execution or a claim in the returned text.

`make check-held-back` uses two signed, synthetic episodes. It compares the actual destination bytes, generates a completion in a separate process from public training examples, and checks an altered token, a wrong-role signature, a later withdrawal, an earlier episode’s reply and a restored decision. A local resident independently returns 42 from two operands. The external example is the seed’s small fitted language model. The resident transformer is covered separately in [resident inference](resident-inference.md).

For the isolated Linux replication, a guest with loopback alone read zero denied bytes and 2,813 bytes for the authorized letter over serial. It generated token 12 followed by EOS and signed the complete 274-byte answer inside the guest. `PROVIDER_WITNESS=/path/to/signed-answer make check-held-back` checks those received bytes with the same broker. The portable source ground uses the public signature vectors in `ground/provider-proofs.ck`. The fixture keys derive from SHA-256 of the UTF-8 text `public synthetic provider test vector v1 owner` and `public synthetic provider test vector v1 listener`. The observed off-host boundary remains open for a separately administered deployment. The broker assumes cooperating processes, an intact local store and provisioned enrollment keys. A crash between external publication and its local decision record can leave a published letter whose later replay is recorded. A repeated local inference can execute again.
